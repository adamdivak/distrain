### 4. NCCL smoke — first contact of the DDP layer with NCCL

```bash
SSH 'cd /workspace/distrain && uv run python scripts/make_synthetic_shards.py --out data/synthetic --shards 2'
SSH 'NCCL_DEBUG=INFO uv run torchrun --standalone --nproc_per_node=2 -m distrain.train \
     --distributed-mode ddp_naive --max-steps 5 --global-batch-seqs 16 --log-every 1 --no-trackio'
# then ddp_bucketed, ddp_interleaved; logs in session_out/smoke_*.log
```

**Worked first try, all three modes.** Transport: `Using network Socket`,
channels `via SHM/direct/direct` — P2P disabled on GeForce as expected, staging
through host shared memory. Train losses across the three modes agree to ≤3e-4
(bf16 noise). Interleaved already visibly faster at batch 8/GPU:
~340 ms vs ~390 ms per step, uncompiled.

### 5. Single-process reference — one OOM, config not code

```bash
SSH '... torchrun --standalone --nproc_per_node=1 -m distrain.train \
     --max-steps 5 --global-batch-seqs 16 --eval-batch-seqs 8 --log-every 1 --no-trackio'
```

First attempt (default `eval_batch_seqs=32`) OOM'd **in eval**: 16-seq training
batch resident + 32-seq eval forward wanted 6.1 GiB more than the 3090 had.
Exactly the decisions.md §4 scenario (eval never shards and is the memory
high-water mark); `--eval-batch-seqs 8` resolves it. Result — **val_loss
identical to 4 decimals across single and all three NCCL modes** at both eval
points (10.9793 → 10.9728): N-GPU == 1-GPU now verified on NCCL, not just gloo.

### 6. Roofline for this box

```bash
SSH 'cd /workspace/distrain && uv run python scripts/measure_roofline.py | tee session_out/roofline.txt'
```

**75.3 TFLOP/s sustained bf16** (fp32 24.0). Aurora's 3090 measures 82.6 — ~9%
spread within one GPU class (power/cooling/card variance). MFU on rented boxes
must use the peak measured *on that box*; the class-level table entry is a
starting point, not a truth.

### 7. Bench matrix — compiled (50 steps, 10 warmup)

```bash
SSH 'cd /workspace/distrain && nohup uv run python scripts/bench_ddp_modes.py \
     --nproc 2 --steps 50 --warmup 10 --out-dir session_out/bench > session_out/bench.log 2>&1 &'
```

| mode | mean ms | vs naive | scaling eff |
|---|---|---|---|
| single | 134.2 | | |
| ddp_naive | 366.5 | 1.00× | 0.37 |
| ddp_bucketed | 374.9 | 0.98× | 0.36 |
| ddp_interleaved | 376.7 | 0.97× | 0.36 |

Comm dominates (~230 ms on 134 ms of compute; scaling 0.37) — and
**interleaved is slowest**, despite being clearly fastest in the uncompiled
smoke. Hypothesis: `torch.compile` runs backward as one fused graph, so the
post-accumulate-grad hooks all fire at the *end* of backward — hook-timing
overlap is structurally dead under compile (the reason real DDP grew
compiled-autograd integration).

### 8. Hypothesis test — same bench, `--no-compile` (30 steps, 5 warmup)

```bash
SSH 'cd /workspace/distrain && uv run python scripts/bench_ddp_modes.py \
     --nproc 2 --steps 30 --warmup 5 --no-compile --out-dir session_out/bench'
```

| mode | mean ms | vs naive | scaling eff |
|---|---|---|---|
| single | 146.3 | | |
| ddp_naive | 383.8 | 1.00× | 0.38 |
| ddp_bucketed | 384.3 | 1.00× | 0.38 |
| ddp_interleaved | **330.9** | **1.16×** | 0.44 |

**Confirmed.** Without compile the overlap works as designed (hides ~53 ms of
comm). Headline: on this transport, *uncompiled interleaved (331 ms) beats every
compiled configuration (367+ ms)* — overlap buys more than compilation when
communication dominates. Naive ≈ bucketed both ways: at 2 ranks over SHM the
transfer is bandwidth-bound and launch-count overhead is noise.

### 9. Bandwidth ceiling — `all_reduce_perf` (2 GPUs, 8M–512M)

```bash
SSH 'cd /root && git clone https://github.com/NVIDIA/nccl-tests && cd nccl-tests && make -j 32'
SSH 'cd /root/nccl-tests && ./build/all_reduce_perf -b 8M -e 512M -f 2 -g 2 | tee /workspace/distrain/session_out/nccl_tests.txt'
```

**Avg bus bandwidth 2.29 GB/s**, flat across sizes. Cross-check: 497 MB of fp32
gradients / 2.29 GB/s ≈ 218 ms ≈ the 237 ms comm overhead the bench measured
(naive − single). The two measurements agree; the ceiling every 2×3090 number
above is interpreted against.

## Session outcomes

1. **NCCL contact: clean, first try, all three modes** — transport
   `Socket + SHM/direct` (GeForce P2P off). The README's biggest unproven is gone.
2. **N-GPU == 1-GPU verified on NCCL**: val_loss identical to 4 decimals across
   single and all three modes.
3. **Mode timing exists** (the measurement the modes were built for) — and it
   found something: `torch.compile` defeats hook-based overlap; uncompiled
   interleaved is the fastest 2×3090 configuration outright.
4. **Roofline 75.3 TFLOP/s** for this box (aurora's same-class card: 82.6) —
   per-box measurement is mandatory, class tables are only hints.
5. **Bandwidth ceiling 2.29 GB/s**, consistent with observed comm overhead.
6. One config lesson re-learned live: default `eval_batch_seqs=32` is the memory
   high-water mark on a 24 GB card once the training batch grows (decisions §4).
7. Cost: well under $1.

## Open questions carried forward

- **Compile × overlap** needs a decision before the cluster session: run Track A
  DDP configs uncompiled (honest hand-rolled overlap, slower compute), or
  compiled (faster compute, no overlap), or investigate compiled-autograd /
  graph-break options so hooks fire during backward. This materially changes the
  slow-network curve's shape — it decides how much comm the fast path can hide.
- The 3090-cloud roofline should be recorded in `mfu.py` `_PEAK_BF16` keyed
  per-host, with the aurora entry kept separate.
