## Timeline

### 1. Provision + first contact

8× A100-SXM4-80GB, driver 580.126.16, 128 vCPU, 2 TB RAM, 80 GB container
disk. **Topology: full `NV12` mesh** — every GPU pair on 12 NVLink lanes,
the fast-interconnect contrast to the 2×3090's Socket+SHM. GPUs 0–3 / 4–7
split across the two NUMA nodes.

### 2. Data download

**Roofline: 269.9 TFLOP/s sustained bf16** (fp32 19.0) — 86.5% of the 312

### 5. NCCL smoke + 8-rank bench matrix

First smoke attempt failed on all four modes in seconds:
`lr_at` asserting `warmup + warmdown < max_steps` — the runbook's smoke
command predated the trapezoid schedule and a 5-step run cannot fit the
default 250/1000. Exactly the "fails loudly" behaviour decisions §13
promised; fixed by passing `--warmup-steps 0 --warmdown-steps 0` (the bench
harness already does), runbook updated.

Rerun: all four modes green at 8 ranks, **val_loss identical to 4 decimals
(10.9429) across naive / bucketed / interleaved / torch**. Transport:
`via P2P/CUMEM/read` on every channel — NVLink P2P, the fast-interconnect
counterpart to the 2×3090's Socket+SHM.

Bench matrix, per-GPU batch 8 (the harness default; global 64 at 8 ranks):

| mode | compiled ms | scaling | uncompiled ms | scaling |
|---|---|---|---|---|
| single | 49.5 | | 86.1 | |
| ddp_naive | 58.8 | 0.84 | 99.8 | 0.86 |
| ddp_bucketed | 58.1 | 0.85 | 95.0 | 0.91 |
| ddp_interleaved | 58.6 | 0.84 | 91.2 | **0.94** |
| ddp_torch | **56.3** | **0.88** | 92.7 | 0.93 |

**The 2×3090 finding does not transfer to NVLink.** Overlap still works
uncompiled (interleaved is best-in-class uncompiled, 0.94 scaling), but at
~200 GB/s the all-reduce is so cheap that compile's compute win dominates:
every compiled config beats every uncompiled one by ~35 ms. The compile ×
overlap question resolves per-transport — compiled `ddp_torch` on fast
interconnect, uncompiled `ddp_interleaved` where comm dominates. Raw
per-step times: `session_out/bench/{20260816T154126Z,20260816T154432Z}/`.

### 6. The converged Track A run

```bash
SSH 'cd /workspace && PYTHONUNBUFFERED=1 OMP_NUM_THREADS=8 nohup torchrun --standalone --nproc_per_node=8 \
  -m distrain.train --train-glob "data/fineweb10B/fineweb_train_*.bin" \
  --val-glob "data/fineweb10B/fineweb_val_*.bin" --distributed-mode ddp_torch --compile \
  --grad-accum-steps 1 --max-steps 9000 --val-every 250 --checkpoint-every 250 \
  --run-name a100x8-fineweb-4.4B > session_out/train.log 2>&1 &'
```

`ddp_torch --compile` per the matrix; per-rank 60 seqs, accum 1, global 480
unchanged. Step-0 fingerprint: train loss **10.8258** = ln 50304 to 4
decimals (zero-init head confirmed). Step-0 *val* printed 10.8125 — 0.014
under the runbook's expected 10.8265; with a zero head the loss is
data-independent, so the deviation is compiled-bf16 eval kernel numerics on
a different GPU class, not a code difference (a non-zero head prints ~10.68).
Steady state: **~318 ms/step, 78% MFU** against the *measured* 269.9 peak —
double the 35–45% the budget assumed. Live stats: `trackio show` on the pod,
tunneled to aurora:7860.

**Early val gates, and an accidental cross-hardware replication.** The
runbook's expected values (≈5.7 @ 250, ≈4.9 @ 500) turned out to be stale —
checked against the trackio DB, aurora's `rotary-calibration-3B` actually
recorded 5.4009 / 4.5076. The pod printed **5.4042 / 4.4987**: agreement to
~0.005–0.009 across a different GPU class *and* a different chunking
(8 ranks × 60 seqs vs single-GPU 60-step accumulation). The
world-size-independence invariants — data order, rank-0 init broadcast, the
two-divisor mean convention — hold on real data at 500 steps, not just in
the gloo tests. (Aurora's step-0 val was 10.8250, also not the runbook's
10.8265; all three step-0 prints are ln 50304 under different kernels.)

### 6a. Credit exhaustion killed pod 1 at ~step 7500–8000

Between the step-6000 val (3.4570, 16:23 UTC) and 16:52 UTC the pod vanished:
SSH refused, then the API returned `pod not found` and an empty pod list.
Account credits had run out; RunPod **terminates** (not stops) pods on a
drained balance, and the container disk — train log, trackio DB, the single
`ckpt.pt` — died with it, ~10 minutes before the run would have finished.
Everything already pulled to aurora (parity result, roofline, nccl, bench
tables, val curve to 6000 via the monitor) survived; the run did not.

Two changes before pod 2, both prompted by this (commit `23eafe5`):

- **Multi-checkpoint retention** — `{run_name}-step{N}.pt`, rolling
  `keep_last` + permanent `keep_every` anchors (default 2000 = the warmdown
  start of the 9000-step schedule, so a dead run can re-enter at max LR).
  `--resume` finds the newest for the run; `--resume-from` names a file.
- **Off-box mirroring** — `checkpoint_mirror` copies each save to another
  filesystem in a rank-0 background thread (skip-if-busy, atomic rename,
  drained at exit). Rehearsed end-to-end on aurora, including SIGKILL
  mid-copy (leaves only an ignorable `.tmp`) and a bit-identical resume
  from the mirror after deleting the local checkpoint dir.

Pod 2 landed in a datacenter the API doesn't name (Houston, TX — network
volumes can't be created there), so the mirror for this session was an
**aurora-side rsync puller** (checkpoints + logs + trackio DB every 2 min)
rather than a RunPod volume; the volume idea stays available for
volume-capable DCs. A second monitor polled the account balance
(alert < $20) so starvation cannot be silent again.

### 6b. The measurement, take two (pod 2)

Parity again on the new image: **129 tests, 2:58** (with `OMP_NUM_THREADS=8`
— §3's 16 min was thread thrash, not the suite). Full re-download (7 min),
relaunch with retention flags. The rerun replicated run 1 *and* aurora's
calibration to bf16 noise a third time (5.3846 @ 250, 4.5151 @ 500,
3.5827 @ 3000, 3.4583 @ 6000).

**The clean 9000-step schedule does not cross 3.28.** Warmdown vals 3.4236 /
3.3921 / 3.3527 / 3.3137, final val **3.2849 at step 8999** — 0.0049 short
at 4.42B tokens. §13's extrapolated ~3.26–3.29 was correct and the run
landed on the wrong side of it. Steady state **311 ms/step, 79.4% MFU**
against the measured 269.9 peak.

**Extension to a clean 10000-step schedule, using the step-8000 anchor.**
Resuming the warmdown-start checkpoint with `--max-steps 10000` is *not* a
§13-style composite: steps 0–8000 of the 9000- and 10000-step trapezoids
are identical by construction (same warmup, same plateau; LR and data are
pure functions of the step), so the resumed run **is** the clean 10000-step
run, 8000 steps already paid. LR re-entered at the full 1.8e-3 plateau, no
§13 re-entry bump — the loss walked straight down: 3.4101 @ 9000, 3.3770 @
9250, 3.3376 @ 9500, 3.3006 @ 9750, and

> **reached target 3.28 at step 9999 after 3147.1s of training** (val 3.2730)

First unsmoothed crossing, training time excluding validation, per the §4
definitions. Cost of the extension: ~12 min, ~$3.

## Session outcomes

1. **Tokens-to-3.28, measured: 4.92B** (crossing at step 9999 of a clean
   10000-step trapezoid, val 3.2730), replacing the 2.95–4.4B bracket. The
   clean **9000**-step schedule ends at **3.2849** — measurably short. The
   modernization's ~2.2× (vs ~10B vanilla) is confirmed at the token level.
2. **Time-to-3.28 on 8×A100 NVLink: 3147.1 s** (52.5 min) of training time,
   ~79% MFU, `ddp_torch --compile`, global batch 480 unchanged.
3. **Image parity proven twice** (125 tests on `de7d093`, 129 on `23eafe5`),
   on baked code with no rsync and no `uv sync`.
4. **Roofline 269.9 TFLOP/s bf16** (86.5% of datasheet); NCCL bus bandwidth
   **154 GB/s avg / 210 GB/s peak** — ~67× the 2×3090 transport.
5. **Compile × overlap resolves per-transport**: on NVLink every compiled
   config beats every uncompiled one (best: `ddp_torch --compile`, 56.3 ms,
   0.88 scaling at batch 8/GPU); uncompiled interleaved still wins its class
   (0.94) — the 2×3090 conclusion does not transfer.
6. **Cross-hardware, cross-chunking replication**: three runs (1×3090
   accum-60, two 8×A100 DDP) match at every shared val point to ≤0.01 —
   the world-size-independence invariants hold on real data.
7. **The credit-exhaustion termination** cost a nearly-finished run and
   produced the checkpoint retention + mirroring that then delivered the
   headline number ~$10 cheaper than a fresh 10000-step run would have.
8. Cost: ~$82 for the session (~$29 pod 1 + ~$53 pod 2) against the $80
   ceiling, overshoot approved for the extension; project total to date
   ~$83 of the $150 target.
